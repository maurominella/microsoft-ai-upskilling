Agents vs Workflows — when to use which

Slide 21

THEME 2 · AGENT FRAMEWORK

Agentic AI on Microsoft Foundry · Day 1

Agents vs Workflows — when to use which

Use an AGENT when…

The task is open-ended or conversational

You need autonomous tool use and planning

A single LLM call (with tools) can suffice

The path isn't known in advance

Use a WORKFLOW when…

The process has well-defined steps

You need explicit control over order

Multiple agents / functions must coordinate

You want checkpoints & human approval

Slide text

Use an AGENT when…

  • The task is open-ended or conversational
  • You need autonomous tool use and planning
  • A single LLM call (with tools) can suffice
  • The path isn't known in advance

Use a WORKFLOW when…

  • The process has well-defined steps
  • You need explicit control over order
  • Multiple agents / functions must coordinate
  • You want checkpoints & human approval

A first agent, in code

C# (.NET)

using Azure.AI.Projects;

using Azure.Identity;

using Microsoft.Agents.AI;

AIAgent agent = new AIProjectClient(

new Uri(foundryProjectEndpoint),

new AzureCliCredential())

.AsAIAgent(

model: "gpt-5-mini",

instructions: "You are a

concise assistant.");

Console.WriteLine(

await agent.RunAsync(

"Largest city in France?"));

Python

from agent_framework.foundry import FoundryChatClient

from azure.identity import AzureCliCredential

 

client = FoundryChatClient(

project_endpoint=ENDPOINT,

model="gpt-5-mini",

credential=AzureCliCredential())

agent = client.as_agent(

name="HelloAgent",

instructions="You are a concise assistant.")

 

await agent.run("...")

The same agent runs locally today and as a Foundry-hosted agent tomorrow — no rewrite.

Same answer either way — but MAF gives you an agent

OpenAI — direct call

client = AzureOpenAI(

azure_ad_token_provider=token,

azure_endpoint=ENDPOINT)

resp = client.responses.create(

model=DEPLOYMENT, input=query)

print(resp.output_text)

→ replies to the query directly

Microsoft Agent Framework

client = OpenAIChatClient(

model=DEPLOYMENT,

credential=AzureCliCredential())

agent = Agent(client=client,

name="Assistant",

instructions="You are a clever agent.")

resp = await agent.run(query)

→ same answer — now from an agent

Identical output for a plain query — but MAF already gives you a named, instructed agent, ready to add tools and memory.

Add a tool: OpenAI returns a call, MAF runs it

OpenAI — direct call

resp = client.responses.create(

model=DEPLOYMENT, input=query,

tools=[protocol_tool_schema])

# the model does NOT run the tool

resp.output_text → empty

resp.output[0].name → tool to call

resp.output[0].call_id → call id

→ only a tool-call request — you run it, then loop back

Microsoft Agent Framework

def ProtocolNumberGenerator():

"""Generate a protocol number."""

return str(random.randint(...))

agent = Agent(client=client,

instructions="Start with the protocol #.",

tools=[ProtocolNumberGenerator])

resp = await agent.run(query)

→ harness runs the tool, returns the final answer

OpenAI returns the tool call for you to run; the MAF harness executes it and returns the finished answer.

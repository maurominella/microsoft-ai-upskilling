Two agent types: Prompt vs Hosted

Prompt agents

Defined by configuration: instructions + model + tools

Authored in the portal, or via SDK / REST

Fully managed — no code, no compute to run

Best for: fast start, production agents without custom orchestration

Hosted agents

Your code: Agent Framework, LangGraph, OpenAI/Anthropic SDK…

Packaged as a container or a zip of source

Foundry runs it: managed endpoint, autoscale, Entra identity, state

Best for: custom code, custom orchestration, multi-agent

Building Hosted Agents with Agent Server

What Agent Server gives you

Templates that receive the calls Foundry sends your agent

A hosting adapter that speaks the Foundry agent contract

Run and debug the agent locally, before publishing

Tooling to push and run the container on Foundry

How you build one

Write the agent logic in your framework of choice

Wrap it with the Agent Server entry point

Add a Dockerfile — or let Foundry build from a source zip

Push the image to a registry such as ACR

Agent Server is not Agent Framework: one writes the agent, the other makes it consumable by Foundry.

Slide text

What Agent Server gives you

Templates that receive the calls Foundry sends your agent

  • A hosting adapter that speaks the Foundry agent contract
  • Run and debug the agent locally, before publishing
  • Tooling to push and run the container on Foundry

Agent Server is not Agent Framework: one writes the agent, the other makes it consumable by Foundry.

How you build one

Write the agent logic in your framework of choice

  • Wrap it with the Agent Server entry point
  • Add a Dockerfile — or let Foundry build from a source zip
  • Push the image to a registry such as ACR

Two agent types: Prompt vs Hosted

Prompt agents

Defined by configuration: instructions + model + tools

Authored in the portal, or via SDK / REST

Fully managed — no code, no compute to run

Best for: fast start, production agents without custom orchestration

Hosted agents

Your code: Agent Framework, LangGraph, OpenAI/Anthropic SDK…

Packaged as a container or a zip of source

Foundry runs it: managed endpoint, autoscale, Entra identity, state

Best for: custom code, custom orchestration, multi-agent

Slide text

Prompt agents

How a Foundry agent works

Agent = Model + Instructions + Tools

Thread

the conversation — holds the message history

Run

one execution of the agent over a thread

Messages

user & agent turns, tool calls & results

The Responses API orchestrates

Receives the user message on a thread

Lets the model decide: answer or call a tool

Executes tool calls, feeds results back, loops

Everything is observable

Each run is fully traced end-to-end

Inspect every model + tool decision

Feeds evaluation and monitoring

Tools: knowledge and action

Knowledge — ground the answer

File search — over documents you attach

Azure AI Search — your enterprise index

SharePoint — governed content grounding

Web / Bing search — public knowledge

Action — do something

OpenAPI & Logic Apps — reach any API/system

MCP servers — standardized external tools

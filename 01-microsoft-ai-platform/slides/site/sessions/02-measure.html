The triad for grounded, retrieval-augmented apps

Slide 18

RAG EVALUATION

The triad for grounded, retrieval-augmented apps

Retrieval

Did search surface the right context, well ranked? Diagnoses the search step.

Groundedness

Is the answer supported by the retrieved context? Diagnoses faithfulness.

Relevance

Does the answer address the user's actual question?

RAG — grounding an app on your documents — is the most common enterprise pattern, so it gets its own evaluation recipe.

The triad localises failure: low retrieval → fix the index/search; good retrieval but low groundedness → fix the prompt/model.

Add response completeness to confirm the answer covered everything the question needed.

Slide 28

AGENT EVALUATORS

Judging behaviour, not just the final answer

Intent resolution

Did the agent correctly understand what the user actually wanted?

Task adherence

Did it stay on task and follow its instructions to completion?

Tool call accuracy

Did it call the right tools, with the right arguments, at the right time?

Agents don't just answer — they plan and act, so we must evaluate the whole trajectory, not only the last message.

These evaluators read the agent's run (messages + tool calls), which ties directly back to Session 1's agents.

Set an acceptance bar — e.g. task adherence ≥ 85% — as a release gate before shipping an agent.

Slide 32

QUALITY · NLP METRICS

Exact, deterministic comparison

F1 score — token overlap between response and ground-truth.

BLEU / ROUGE / METEOR / GLEU — classic text-similarity metrics from NLP.

Deterministic and cheap: no model call, perfectly repeatable.

Best when you have a reference answer and care about exact wording (extraction, translation, summarisation).

AI-ASSISTED VS NLP

Use NLP metrics for exact comparison against a reference; use AI-assisted evaluators for nuanced, reference-free quality. Often you use both.

LOCAL EVALUATION

The inner loop, with the SDK

Slide 42

LOCAL EVALUATION

The inner loop, with the SDK

The azure-ai-evaluation SDK runs evaluators on your machine against a local dataset.

One evaluate() call runs many evaluators over a JSONL dataset and returns per-row + aggregate scores.

Instant feedback while you tweak a prompt or an agent — the tight developer loop.

Human-in-the-loop: you can also review and label a handful of cases by hand for a gut check.

from azure.ai.evaluation import evaluate result = evaluate( data="dataset.jsonl", evaluators={ "groundedness": grounded, "relevance": relevance }, ) print(result["metrics"])

CUSTOM EVALUATORS

When built-in isn't enough

Code-based

A Python function/class that returns a score

Deterministic business rules (format, length, must-contain, PII-free…)

Full control, no model call needed

Prompt-based

An LLM-as-judge you define with a Prompty template

For nuanced, domain-specific quality criteria

You write the rubric; the model applies it

Custom evaluators live in the same catalog and run locally or in the cloud, exactly like built-in ones.
